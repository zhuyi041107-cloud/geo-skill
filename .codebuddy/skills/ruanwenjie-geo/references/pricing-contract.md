# 按本次指令报价

## 指令与约束来源

plan.pricing是3.0计划的唯一报价来源。instructions准确记录本次用户关于档数、费用、数量、服务和税费的原话或忠实摘要。无当前指令，不从参考件、旧客户或旧代码猜价格。用户可以明确最低媒体费、写作单价或两档配置，但没有要求时这些都不是默认。

预算目标budget_target只作参考；只有“不能超过／最高”等明确上限才填budget_limit。只有预算不代表已有服务报价。project若有显式budget_limit，必须和pricing一致，冲突时WorkBuddy依据最新要求更新内部派生副本，不改客户原件；旧project预算目标不自动约束新报价，旧analysis.budget不覆盖本版核算。

## 最小结构

pricing包含instructions、三位currency、tax_note、options；选填budget_target、budget_limit、minimum_total、minimum_media_total、required_option_count。只有用户明确提出最低费或档数时才填对应约束。

options是本次需要的一档或多档，每档只有name与items。明细包含name、category、billing、covers，可选note。category为media/writing/service/package，用于区分媒体、写作、服务和整包。

| billing | 必填计价字段 | 含义 |
| --- | --- | --- |
| unit | quantity正整数、unit、unit_price | 明确单价×数量 |
| package | amount | 用户明确整包价，包含范围由covers列出 |
| included | 不填金额 | 该服务已包含，不重复另收 |
| client_provided | 不填金额 | 客户供稿或客户自行操作 |
| not_included | 不填金额 | 本方案不承接，不能在动作中当已含交付 |
| unquoted | 不填金额 | 服务价尚未确认；不是免费或0元 |

单价与金额用两位小数字符串。程序用十进制相乘汇总，不允许手填subtotal/total覆盖核算。未知项使总价为未确定，只显示已明确部分；不能拿未知金额0来声称在预算内。

## 服务覆盖与避免重复收费

plan.service_scope每项包含id、task、provider、client、action_ids，明确软文街做什么、客户配合什么，以及关联哪些动作。covers引用这些工作ID。每档须交代所有scope的包含／另计／客户提供或不承接状态；同一项scope不能被两条费用重复覆盖。

若三类媒体分项报价，应按可独立计价工作拆scope，如权威媒体刊发、行业媒体刊发、自媒体刊发，不把同一个“媒体发布”scope重复收费。整包已含策划、写作和媒体时，让包价covers对应工作，不再额外列同一写作费。一个工作不能改名拆成重复收费。

独立稿数与刊发次数分别理解；同稿增发只有媒体次数变化，不自动增加写稿数。用户可以明确不同档的数量与权益差异，新版不强制两档同刊次；但同一档各处的数量、阶段和服务描述须一致，不能凭预算余额凑稿。

## 缺价与修改

没有明确单价／整包价时保留unquoted，并将已知预算作为规划框架，不造“建议采购成本”“已落实资源”或无依据服务费。税费口径未提供写“税费待确认”，不自动加税率。追加服务须与本次授权及报价一致，不在正文承诺、费用页再全部另议。

用户明确变更档数、单价、写作包含范围或上限后，先更新同一plan的instructions和数值，重新导出；不改校验器、不复用旧analysis里的金额。费用页自动显示明细、包含范围、报价合计、明确上限和可计算余额。检查每个报价档独立满足用户约束；未知或冲突不能伪装成已确定报价。

2—3档的工作范围、名称、类别、计价方式、单位和说明相同时，费用页自动横向比较各档的真实数量、单价及小计，共用范围只列一行；范围或说明不同、超过3档时继续逐档列明。该排版选择不改变金额与收费状态，待报价仍使该档总价和余额待确认，报价均由同一pricing核算。

## 两种可接受用法

- 用户明确一档2万元整包、含策划和写作：一档package=20000覆盖这些服务；不加旧最低媒体费或100元写作增项。
- 用户明确媒体刊次与单价、正文每篇180元另计：按本次的三类媒体各项和独立稿数核写作；不退回旧分类价或示例两档。

仅有“意向预算2万元”时，上述两种价格都不能自动推导出来。所有参考案例的旧价、折扣、充值赠款、采购与客户报价分别对待，不以旧样例作为本案已确认指令。
