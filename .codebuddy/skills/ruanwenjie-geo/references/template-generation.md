# 固定页式生成说明

版本：0.8.0。制作报告前完整阅读本文件。诊断固定8页、执行方案固定9页，均为横版；随包固定背景保留视觉、标题位置与内容区域，客户生成仅填专属文字与数据。两份报告分别承担诊断与售前执行职责，详细字段见 [PDF填写规范](pdf-output.md)，命令见 [数据与命令](commands.md)。

## 1. 先完成内部规划，再生成客户JSON

文件按职责分开：

| 文件 | 内容 | 交付范围 |
| --- | --- | --- |
| project.json | 客户、目标、问题、预算与已有条件 | 内部 |
| analysis.json | 完整答案判读、截图／引用、事实支持、未知及统计 | 内部 |
| plan.json | 内容组与任务依据、独立稿数、媒体推荐池、实际发布、阶段与金额核算 | 内部 |
| report.json | 本案独立重写的8页诊断及9页执行客户成稿 | 仅用于生成客户PDF |

前三类及原始材料保留在客户目录的.work或原件位置。report只含客户可见内容，不复制analysis/plan后隐藏内部字段；原题、原答、截图、证据关系、采集条件、内部ID、经营判断与检查台账不进入客户JSON或导出附件。

按 [报告分析思路](report-thinking.md) 在现有底稿接通：事实→优先场景→选择理由→内容任务→信源与媒体作用→阶段数量及费用。已有信息直接复用，plan中的logic_links记录这条关系，不把关联数量当独立稿数。无需另造平行台账。

售前先按有独立价值的内容组形成总数量、阶段和媒体预算，再填客户方案；标题可作为方向示例，不要求预先写死每篇文章和每周日期。已签约后若委托详细大纲，沿同一内容组与确认版本细化，不另起一套数量。

## 2. 诊断：固定8页

| 页 | 标题 | 本案应写的内容 |
| --- | --- | --- |
| 1 | GEO品牌诊断 | 品牌主体、业务范围、日期及一句总体判断 |
| 2 | 品牌在AI中的认知现状 | 实际取得答案的平台如何认识品牌、主营与采购场景，及具体业务影响 |
| 3 | 同行AI认知对比 | 相关同行在实际答案中的印象及选择理由，说明客户应提炼什么认知方向 |
| 4 | 品牌优势与已有基础 | 客户已有产品、服务、案例和可公开事实，说明在何种条件下支持用户选择 |
| 5 | 信息冲突汇总 | 主体、业务和服务范围的实际冲突、影响及修正动作；没有实质冲突时写一致状态与维护建议 |
| 6 | 重点业务场景布局 | 综合需求、事实、AI表现、商业目标与执行条件，推荐首批、后续或暂缓方向并说明理由 |
| 7 | 内容建设与执行分工 | 具体建设什么内容与载体，软文街负责什么、贵司需配合什么 |
| 8 | 推进计划与阶段复核 | 阶段工作、交付、双方分工及观察目标，周期按本案条件确定 |

第4页优势要能支持第6页场景，第6页优先方向必须在第7、8页找到具体动作。第6页页底用简短一句说明“具体能力→优先场景→选择价值”，自然改写为本案建议，不填关系占位词。

同行的AI印象与已核企业事实分开；目标标签是拟建立的认知方向，不能写成现有模型属性。没有实质冲突不编造冲突，没有相关同行不补名单，未调查的平台不补结论或空白结论页。单平台也按8页完整组织。

## 3. 执行方案：固定9页

| 页 | 标题 | 本案应写的内容 |
| --- | --- | --- |
| 1 | GEO落地执行方案 | 品牌、方案名称、目标及本期执行重点 |
| 2 | 品牌印象与目标标签 | 当前品牌印象、事实支持的目标认知及重点场景；现状与目标分开 |
| 3 | GEO执行思路 | 从现有印象与客户事实到场景内容、媒体发布、阶段复核的工作关系 |
| 4 | 内容建设规划 | 按内容组说明主题、具体业务要点、采用的事实、独立稿数及作用；不展开逐篇矩阵 |
| 5 | 媒体发布规划 | 具体资源／栏目、内容用途、发布类别与数量，说明为何适配；完整候选另在推荐媒体Excel |
| 6 | 阶段目标划分 | 阶段重点、优先理由、内容增量、独立稿数、发布量、周期、费用及必要配合 |
| 7 | 执行分工与贵司配合 | 双方负责事项、材料和审核节点，说明可并行任务与仅影响特定内容的依赖 |
| 8 | 阶段复测与优化 | 分别观察品牌事实、场景候选和推荐理由，什么变化触发后续内容或媒体调整 |
| 9 | 费用方案 | 实际可执行方案的总价、规模、媒体数量与价格、阶段金额及包含范围；未计费用清楚说明 |

先承接诊断的优先场景与选择理由，再落实内容和媒体。首批已有事实可支持场景、选型或案例时直接安排，不强制先发整批品牌介绍；官网修正与已核内容可并行。材料不到位时，具体说明受影响内容及可先开展的工作。

售前数量来自内部规划，客户页呈现方向、数量与成本，不附逐周或逐篇台账。已确认合同与权益不因排版改变；涉及内容规模、媒体、周期或费用调整时，保留旧→新关系并按已有授权处理。

### 费用页与方案档位

约2万元默认及报价口径统一见 [证据与规划](evidence-and-planning.md)。第4、5、6、9页采用同一plan中的内容组、独立稿数、发布量与金额；改规模先改真实任务，再改阶段、媒体和报价，不能只改费用页。

只有一套实际执行组合时呈现一套报价。确已规划普通／高权重两套方案时，使用同内容、同独立稿数比较，差价对应具体媒体单价或配置，同内容两档也保持发布量一致；不能只为填双栏编出第二套。六档目录价格是媒体原价档位，不自动等于这两套客户方案。

媒体费按实际发布次数计算，写稿等费用仅在确有服务范围和报价时纳入。同稿多站不增加独立稿数；额外增发须有明确任务和用户同意，不能由记账规则自行扩量。客户要求综合总预算时，已知服务费也占总预算，不先花满媒体费再附加。

## 4. 客户语言与信息边界

客户成稿依次说清品牌现状、场景与同行差距、业务影响、具体行动。每项建议包含具体对象、业务内容或载体、用途、分工和检查节点；示例是拟开展内容，实际能力、参数、案例过程和效果来自客户事实。

对外使用“贵司”，页面标题沿上述专业名称，文章示例标题可按读者任务使用自然问句。页底只写本页结论或建议，不写页面目的、核查指令或“本页重点”。避免重复摘要、泛化提示和只有标签没有解释的判断。

平台现状只归属实际有对应回答的平台；图标不是已完成调查的证据。不把API、网页或App观察互相冒认，也不把一题结果扩成全平台表现。内部保留这些条件，客户正文不夹原问原答、截图、来源链、模型版本、样本数量、采集说明或笼统样本免责声明。

缺少支持的结论收窄或删除，重要业务未知转成对应事项的具体核实与配合动作。无URL截图仍可支持可见来源结构，不要求客户另抄链接后才交报告。不得把未知写成无、把客户意愿写成结果，或用“待核”小字保留没有依据的主张。

## 5. 固定背景填充

report.json按当前schema填写诊断与执行各页客户文案，背景、标题位置、图形和可用区域由随包模板与渲染器管理。export_pdf.py是生成两份客户PDF的唯一入口，具体参数见PDF填写规范；客户生成不另写临时排版脚本或改变页面背景。

先写清业务内容，再压缩重复表达以适应文字区域；超出时修订成稿并重导。保留客户决策必需的事实、费用和责任，不能截字、藏字或靠无限缩小字号凑页。随包背景不携带真实客户内容，示例名称、数字与现状不继承。

PDF填充使用本包依赖及随包资源；客户生成不以本机浏览器或另外安装字体为前置。具体缺项按当前生成器错误处理并保留数据，不用临时替代模板冒充通过。

## 6. 推荐媒体Excel

媒体池与执行子集分别维护：plan.media_recommendations独立广泛列资源，plan.placements核实际费用。推荐数量不受预算、刊次或执行排期限制，不把只选预算内几家媒体当完整推荐。

使用原推荐媒体模板，sheet1网络媒体、sheet2自媒体，保持原16/17列及六档原价；具体检索、字段、可发条件及导出规则统一见 [推荐媒体Excel规范](media-word-output.md)。导出默认三件客户成品。

## 7. 交付前另轮自审

1. **对齐本次要求。**核最新用户要求、材料与有效权益，明确必需项、受众、格式及限制；旧默认不覆盖新要求。
2. **通读最终成稿。**从客户老板视角逐页判断是否有助于理解现状、选择理由、主攻方向、具体动作、数量、周期费用和配合。无决策信息的重复过程删除或合并。
3. **双向核内容。**诊断优先场景在执行内容组与首批阶段有落点，主要内容能回到事实与选择理由；暂缓有具体原因，知识稿不冒充品牌任务完成。
4. **核数量费用。**内容组独立稿数＝阶段稿数＝总稿数，发布明细＝媒体及阶段发布次数，数量×单价及费用包含范围一致。推荐池不计支出，客户稿金额与内部计划同源。
5. **核实际文件。**打开或渲染诊断8页、执行9页及两张媒体sheet，检查文字、图标、位置、表格、遮挡、截断、占位及旧案例残留。固定页数正确不代替内容或视觉通过。
6. **修正后复查。**改了文案或数据就检查受影响页面及汇总，重新导出后核新版；内部简记实际检查及剩余状态，不增加客户自审页。

存在影响结论、执行或报价的关键问题时先用已有材料修正；不能解决的准确说明具体剩余项，不假称正式完成。单平台、缺采集模式或截图无URL本身不构成停交理由。默认完成是两份PDF及一个推荐媒体.xlsx已经生成并检查，不能只交聊天摘要。
