# 固定页式生成说明

版本：0.12.0。报告制作前完整阅读。诊断8页、执行9页，统一1200×675横版；使用旧版参考的固定背景和内容区，只替换客户文字及同源计划数据。WorkBuddy直接完成分析、成稿和另轮逐页自审；字段见[PDF填写规范](pdf-output.md)，运行见[本地命令](commands.md)，不依赖MCP或外部模型服务。

## 1. 内部分析与客户成稿分开

| 文件 | 职责 | 交付范围 |
| --- | --- | --- |
| project.json | 客户业务、目标、问题、已有条件及明确预算约束 | 内部.work |
| analysis.json | 完整回答判读、来源与事实状态、必要统计 | 内部.work |
| plan.json | 内容组、三类角色与计划刊次、阶段、两档配置及服务范围 | 内部.work |
| report.json | 独立撰写的8页诊断与9页执行客户文字 | 仅用于生成客户PDF |

先按[分析思路](report-thinking.md)完成判断与计划，已有材料直接复用。plan.logic_links保留发现、选择理由、内容或客户动作、媒体作用、阶段与检查关系；同一任务关联多个目标仍只计一次。

客户JSON只含可见成稿，不复制内部文件后隐藏字段。原题原答、截图、采集条件、内部ID、证据链、毛利和检查台账留.work，不进入附录或客户文件的隐藏数据。

## 2. 诊断的8页职责与版式

| 页 | 标题与固定形式 | 应写内容 |
| --- | --- | --- |
| 1 | GEO品牌诊断，封面 | 品牌、主体、主营、日期与核心业务判断；元信息只保留本案必要内容 |
| 2 | 品牌在AI中的认知现状，三卡 | 实际品牌印象、自然选择表现及主要影响；具体说明哪些优势尚未成为选择理由 |
| 3 | 同行AI认知对比，比较三卡 | 相关同行与本品牌直接比较，提炼自身有事实支撑的选择方向 |
| 4 | 品牌优势与已有基础，三列表 | 已有做法、客户提供的服务事实及其内容使用和选择价值；自述与已核分清 |
| 5 | 信息冲突汇总，四列表 | 对比项、当前状态、具体差异、调整建议；无实质冲突时写已统一情况和维护事项 |
| 6 | 重点业务场景布局，重点区与场景卡 | 根据商业价值、真实优势和材料条件给出首批、随后、暂缓及理由 |
| 7 | 内容建设与执行分工，三列表 | 工作事项／软文街负责／贵司配合；责任具体对应内容、事实、授权和载体 |
| 8 | 推进计划与阶段复核，四块 | 起步并行事项、首阶段、后续拓展、持续复核与调整；保持实际材料依赖 |

第3页从同行回到本品牌，第4页事实支撑第6页场景，第6页优先方向在第7、8页有动作。优先核心商业场景，身份、合规及售后说明可同步补强，不能让品牌纠错替代整个获客方案。

同行不足时收窄对比，不能补造名单。新增证书、案例、数量、服务承诺按实际材料限定；投诉是消费者陈述还是已核结果需分清，AI复述的同行宣传不能升级为事实。

## 3. 执行的9页职责与版式

| 页 | 标题与固定形式 | 应写内容 |
| --- | --- | --- |
| 1 | GEO落地执行方案，封面 | 目标、核心选择理由、本期规模与执行重点 |
| 2 | 品牌印象与目标标签，三卡 | 当前品牌印象／同行认知差异／本期目标方向，说明客户凭什么被选 |
| 3 | GEO执行思路，四步2×2 | 明确选择差距、整理真实服务、内容与发布、复核后调整；文字按本案展开 |
| 4 | 内容建设规划，四列表 | 内容组、同源稿数、具体业务要点和作用，不展开密集逐篇矩阵 |
| 5 | 媒体发布规划，三卡 | 权威媒体／行业媒体／自媒体，各列内容用途、计划刊次及两档费用；具体媒体待确认 |
| 6 | 阶段目标划分，1至4阶段卡 | 商业场景、具体增量、日期、独立稿数、三类刊发数、普通与高权重两档阶段费用及客户配合 |
| 7 | 执行分工与贵司配合，三列表 | 工作事项／软文街负责／贵司配合，直接使用plan同源服务范围 |
| 8 | 阶段复测与优化，三列表 | 复核方向／观察重点／后续调整，明确节点及服务是否已含 |
| 9 | 费用方案，两档卡 | 普通权重与高权重，同稿同刊；三类媒体分项、媒体费已含服务、独立写作费及两档含写作总价 |

首批按商业价值和已有事实安排，场景内容与主体、官方说明并行。某些案例或授权未到位时，说明具体受影响内容及可先开展工作，不无条件等全部材料齐全，也不提前承诺待核主张。

售前先完成内部内容组、独立任务数量和两档分类报价，再展示方向与规模。签约后详细大纲承接同一规划，不因后续逐篇化再加一套数量。原参考的72篇、16周及三类24／36／12是历史规模与验算例，不强制新客户照搬。

## 4. 两档报价和服务范围

唯一价格与预算规则见[证据与规划](evidence-and-planning.md#普通与高权重两档客户报价)。第4、5、6、9页从同一plan取数；主计划为普通档，高档使用同一类别及刊次，两档同内容、同独立稿数、同每稿刊发次数。

第5页按三类角色说明内容用途、两档费用和刊发量，第6页列两档阶段金额，第9页对照三类分项和完整服务费用。不列具体媒体名称、账号或栏目；资源、刊发条件与两档实际权益差异待确认，不能把“高权重”名称当作已落实资源或AI效果保证。

第7页与第9页使用同一plan.service_scope：媒体费已含选题、大纲与素材方向、媒体发布、链接汇总和阶段复核；执行文章的AI起草、正文撰稿及人工修改均不含在媒体费中。默认separate模式，写作原价200元／篇、打包100元／独立稿，单列写作费及两档含写作总价；client_provided由客户供稿，不收写作费。客户自行核准事实、定稿授权、操作官方载体并处理真实服务争议。实际改站、页面建设、额外维护等若另行承接，先明确范围和价格再列交付，不前文承诺后文全部另议。

每档媒体费最低12,000元，通过有价值的实际内容、媒体与刊次核算达到，写作费不能充抵最低媒体费；不虚加补差或凑无价值投放。budget_target只是意向目标，只有本轮客户明确不能超过的budget_limit才是硬上限。无硬上限按完整业务任务计算两档；任一档超硬上限时调整真实规模和配置，同时保留最低媒体费要求，不降标准单价、不虚增优惠或隐去写作费。条件确实冲突时先明确冲突，不制造可执行假报价。

## 5. 客户语言与事实边界

正文和页底只写本案现状、业务差异、选择理由、动作、分工与费用。将内部写作命令改成具体业务判断：例如写“试课用于判断方向是否匹配”，不写“目标标签只写事实能支持的部分”；写具体内容分工，不写“避免同义标题重复计篇”。

原始提问、答案、截图、模型版本、采集条件、样本数量、整理过程、计数规则和笼统免责声明留内部。必要未知在对应业务事实旁简短说明，不用“待核”小字保留无依据结论。

不承诺客户必然流失、稳定第一、发稿必被引用或指定名次。未调查平台不补结论；引用、自有榜单、转载与独立证实分清。目标认知是计划，不是已有结果。

## 6. 固定背景与交付

本版不检索或推荐具体媒体，不生成推荐媒体表；只交两份PDF。历史媒体目录、旧推荐表及客户旧成品保留，不用于本轮分类方案。export_pdf.py按固定背景导出，不改模板、schema、坐标或字号绕过溢出；文字过长时精简内容后重导。

## 7. 交付前另轮自审

1. 对照本次要求与客户事实，核是否形成自身选择理由，而非只剩主体纠错、风险治理和通用科普。
2. 核诊断优先场景是否进入首批及后续内容，暂缓条件是否与排期一致，相关事实和材料是否支撑。
3. 核三类媒体的内容职责、两档计划刊次和价格；普通和高档同范围，具体媒体及权益差异尚待确认。
4. 核每档实际媒体费不低于12,000元，双方分工与费用包含清单逐项一致，执行文章写作另列费且不重复计入媒体费；意向预算没有被误当硬上限，含写作总价和复核节点清楚。
5. 通读最终客户文字，删制作规则、处理过程、计数解释、泛化提示与过度结论。
6. 实际打开或渲染诊断8页、执行9页，逐页核字体、标题、表格、三卡、报价、遮挡、截断和案例残留；修订后再查变动页及相关汇总。

WorkBuddy另起一轮自审，读取原依据、原模板和实际17页图，修正后重导并复查。仅自审通过后复制两份PDF至新的正式目录，并核复制文件与已审文件一致；审核意见与制作材料留内部，不要求外部GPT审批。只回传一个平台、模式缺项或截图无URL本身不构成停交理由。维护skill时用虚构客户测试，真实旧报告只作只读版式依据，不重做、不覆盖，也不上传原客户文字。

# 固定模板PDF填写规范

两个PDF均为1200×675横版：诊断固定8页、执行固定9页，保留用户认可旧版的背景、表格、卡片、标题与字号。`scripts/export_pdf.py`是本地渲染入口，共享渲染器只填固定文字区；ReportLab绘制文字层，PyMuPDF合成背景和预览。WorkBuddy直接分析、成稿与逐页自审；全流程无需MCP、API密钥、浏览器渲染或GEO云端工具。

## 客户配置与内部计划

先完整读[逐页生成说明](template-generation.md)，再参考[客户示例](report.example.json)和[schema](customer-report.schema.json)填写：

```json
{
  "schema_version": "2.0",
  "customer": {
    "brand": "客户品牌",
    "company": "客户运营主体",
    "date": "2026-11-11",
    "observed_platforms": ["豆包"]
  },
  "purpose": "本案业务目标",
  "diagnosis": {"pages": []},
  "execution": {"pages": []}
}
```

这是根结构，空pages不能导出。实际页标题、顺序、layout和字段按当前schema与示例，不从旧0.8客户JSON直接复用不同布局。`observed_platforms`只列实际有回答的平台；已知平台用图标，其他平台用文字，不能保留未调查平台标识。

report只存客户可见稿；内部原答、截图、来源链、条件、ID、核算与logic_links保留.work。客户稿不手填computed数据，也不用额外字段夹带内部资料。

| 8 | summary4 | 四项title／body，起步、首阶段、后续、持续复核 |

## 分类汇总，不指定具体媒体

`placements.strategy_role`为权威媒体、行业媒体、自媒体三类，`strategy_basis`说明该类别的传播用途，不填写具体媒体、账号、栏目或来源。媒体页自动显示三类计划刊次和两档小计，并提示具体媒体待确认；两档实际资源与权益差异尚未确定，不能表述为已选定或保证效果。无推荐Excel。

## 同源数量、服务和两档费用

project、contents、stages、主placements、quote_options及service_scope是核算来源，作者只写业务解释。主plan为普通档，quote_options严格一项高权重分类报价，内容、独立稿数和每稿刊次相同。每档媒体费按计划刊次核算且最低12,000元，不虚加补差，写作另收费。固定客户单价、写作费和预算边界统一见[费用规则](evidence-and-planning.md#普通与高权重两档客户报价)。

入口向内容组注入稿数，向三类媒体卡注入计划刊次和金额，向阶段注入日期、三类数量和两档费用。第9页同时给两档三类媒体费用、媒体费已含服务、独立写作费和含写作总价；客户JSON不得手填另一套合计或收费scope覆盖同源数据。

执行7从service_scope.work_items生成双方表，执行9按included项列基本服务；这些基础工作只含选题、大纲与素材方向等约定服务，不含执行文章的AI起草、正文撰稿或人工修改。service_scope.writing_mode=separate为默认写作单独收费分支，从manual_writing按原价200元／篇、打包100元／独立稿核写作费；client_provided时显示客户供稿且不收写作费。旧ai_assisted免费含起草模式不再适用。review_schedule明确复核节点。任务正文和服务范围有矛盾时先修计划，不用“另议”掩盖已承诺工作。

budget_target为意向预算，不自动成为硬上限；客户明确不能超过时才设budget_limit。无明确硬上限按完整任务核两档，每档实际媒体费均须达到12,000元。任一档超硬上限时重新配置实际范围，不改固定单价或藏写作费；最低媒体费与硬上限无法同时满足时明确说明冲突，不导出不合规报价。72稿与24／36／12是公式验算例，不是通用篇数或固定媒体比例。

## 生成和成品检查

Python 3.10或更新版本，按requirements.txt安装openpyxl、ReportLab、PyMuPDF。字体、背景、图标随包；无需Node、Chrome、Edge或Codex私有运行时。

```text
python "技能目录/scripts/export_pdf.py" --analysis "客户目录/.work/analysis-final.json" --plan "客户目录/.work/plan.json" --report "客户目录/.work/report.json" --output-dir "客户目录/正式输出/客户PDF"
```

`--report`、`--output-dir`必填；默认`--kind both`，另可选diagnosis或execution。诊断可独立生成；执行需要plan，项目取`--project`或analysis.project。提供analysis时预算须和当前计划一致，实际参数用`--help`核对。

客户PDF目录只新增两PDF。PNG与审计自动放report同级pdf-review（通常在.work），结果返回review_dir和audit；直接使用技能示例时放输出父目录.work，不写回技能。同名成果拒绝覆盖，使用新版本目录。

背景与schema由assets/report-assets-manifest.json按字节数及SHA256封版。客户生成只改数据，溢出时精简重复表达，不换模板、不截字、不缩字号或自动增页。导出后逐页看17张实际画面，核固定标题、表格、三类卡、分工、双档费用和中文；再核全部数量和服务范围，文本提取不能替代视觉。

公开仓库只放清除客户文字的背景、配套资源和虚构示例，真实客户PDF、截图、回答和本地审计不上传。修改skill以虚构资料验证，不重做客户旧报告。本地渲染、迁移安装和WorkBuddy界面实测分别记录。
