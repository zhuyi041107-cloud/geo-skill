# 软文街 GEO 诊断与执行规划

给WorkBuddy使用的内部业务技能：客户资料 → 三列人工AI回答采集表 → 业务分析与独立客户成稿 → 固定8页诊断PDF、9页执行方案PDF、六档原价推荐媒体Excel。

## 0.8.0 的执行方式

- 问题从实际采购判断出发，按真实需求、诊断用途与信息增量筛选；不设固定题数、不按分类凑题。
- 同事只填“问题、引用截图、答案”。收到任一平台回答，直接完成该范围的诊断和执行方案；截图无完整URL继续分析，不补问模式、联网或模型后才交付。
- 诊断固定8页横版、执行固定9页横版，使用随包背景填充客户文案。页面职责继承新包的诊断与执行逻辑，客户生成不重新设计背景或另写排版脚本。
- 客户report.json独立于内部analysis/plan。客户正文说明品牌现状、场景与同行差异、业务影响和行动；原答、采集状态、来源关系、内部台账与经营判断留.work。
- 规划接通“事实→场景→选择理由→内容→信源→阶段费用”。售前先完成内部内容组、数量与成本，客户呈现方向和规模；合作后详细大纲再细化逐篇与逐周排期。
- 首批按场景价值与真实依赖安排，已核事实可直接支持选择、比较或案例内容；不固定先发整批品牌介绍。
- 未给其他预算时，实际执行目标及上限为20,000元，正式建议的已知费用通常为18,000—20,000元。真实任务、数量和原价可复算，不抬价或凑量。
- 推荐池独立于执行预算。网络媒体、自媒体分别广泛筛选适配资源，推荐媒体.xlsx的sheet1、sheet2保留原16/17列、分组和六档原价；预算内placements只记录实际执行子集。
- 只有确实制定两套可核算计划时才展示普通／高权重两方案，同内容独立稿数与发布量一致；一套计划就展示一套，不把媒体六档原价当方案档位。
- 完成后另轮做客户视角、事实、数量费用和17页实际文件检查；生成成功或页数正确不代替内容与视觉验收。

本版只整合本地写作、诊断与执行逻辑，不迁移云端GEO工具，不自动采集、调用收费模型、配置监测、操作账号或执行发布。客户资料、旧成品和实采回答不写回技能仓库。

完整规则见 [SKILL.md](.codebuddy/skills/ruanwenjie-geo/SKILL.md)、[固定页式生成说明](.codebuddy/skills/ruanwenjie-geo/references/template-generation.md) 和 [PDF填写规范](.codebuddy/skills/ruanwenjie-geo/references/pdf-output.md)。模板背景保留视觉，客户事实、结论、篇数、阶段与金额逐案填写，历史案例不是新客户事实。

## 使用

首次给客户资料：

> 根据客户业务和获客目标，按采购判断生成真正有诊断价值的问题，给我“问题、引用截图、答案”三列AI回答采集表，等我回传。

回传任意平台回答：

> 用已回传答案直接完成本轮诊断和执行方案。按固定8页诊断、9页执行填写本客户内容，客户正文不加采集说明或样本免责声明。默认约2万元用于实际执行；推荐媒体按网络/自媒体分别广泛列出，不限预算内已选媒体。交两份PDF和六档原价推荐媒体.xlsx，内部数据留.work。

默认只交：

- GEO诊断报告.pdf
- 品牌传播与GEO执行方案.pdf
- 推荐媒体.xlsx（sheet1网络媒体、sheet2自媒体）

客户目录保留原件，内部project、analysis、plan、判读与核算留.work，report.json只用于客户成稿。旧成品不覆盖，修订使用新版本目录。PDF费用来自实际placements与已约定费用，推荐Excel来自更广的media_recommendations，其资源标价总额不计客户预算。

## 内置媒体资源

随包提供网络媒体和自媒体资源目录，media.py可直接查询，无需同事另传报价。目录保留资源身份、分类、地域、限制、原记录索引及六档原价：市场价格、超级代理、核心代理、高级代理、普通代理、普通会员。

`--limit 0`读取相关匹配全量，再按实际适配筛选；明确拒发剔除，条件资源保留限制。默认执行预算采用市场参考价，有已确认客户售价时按该口径计算；市场价不等于内部成本。六档从原目录填齐，真实缺价才留空，不按折扣反算。更新报价须有来源与日期，优先于旧目录。

公开仓库按要求保留六档报价，不分发供应商身份、实际联系方式、原始报价XLSX、真实客户材料或实采回答。推荐池不表示全部购买，执行和发布按另外的明确授权进行。
